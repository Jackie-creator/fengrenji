# ruassist（俄语助手）— 项目记忆

面向中文母语学习者的离线俄汉词典与学习工具。对标法语助手／德语助手／西语助手的功能骨架。

> 本文件只管 `ruassist/` 子目录。仓库根目录的 `CLAUDE.md` 是 LeatherPattern AI（皮具项目）的，
> 与本项目无关，两套约定不要互相套用。

## 不可违背的架构铁律

- **作者提供分类与意义，引擎提供词形。** 词条永远不手写变格变位表；作者只标注扎利兹尼亚克
  范式索引，构建期由形态引擎展开。只有范式生成不出来的补充形式才写进 `form_overrides`。
- **运行时零模型调用。** 产品是纯离线的确定性数据。允许在**构建期**用模型辅助生成中文释义草稿，
  但必须经审校后固化入库；用户看到的每个字都是审校过的数据。
- **每一个词形都必须带重音。** 缺重音是构建失败，不是警告。
- 手写数据当代码对待：改词库要跑 `pytest`，`verify` 清单发布前必须清空。
- 无服务器、无账号（M4 之前）；生词本与复习进度存客户端本地。

- ✅ M0 数据地基：schema 定稿、重音规范、校验器、55 词难样本样例

- ✅ M1 形态引擎：范式展开、词形还原（含歧义候选）、CLI 查词、OpenCorpora 交叉核验
- ✅ M2 词典查询层：四级模糊查、拉丁转写输入、词条组装、离线词包构建（发音待做）

## 已确认的决策（与产品负责人讨论过，勿自行更改）

- **不做产品内 AI 功能**（口语陪练、作文批改、实时讲解）。词典与形态引擎是刚需，先做透。
- 基础功能必须**离线可用**——这是法语助手那套产品的护城河，也是本项目的硬要求。
- **客户端不跑形态引擎**：构建期把词形全部展开成查找表（FST/DAWG），客户端只查表。
  pymorphy3 是 Python 的，进不了浏览器，但运行时根本不需要它。
- 平台 **Web 优先**（PWA），将来用 Tauri 包成桌面版。
- 中文释义由本项目**自己撰写**，因为开源俄语数据（OpenRussian／Wiktionary）只有英德释义。
- 词形、重音、范式**必须来自开源形态数据**（OpenCorpora／OpenRussian）交叉核验，不能靠手写。
- 规模不对标法语助手的几十万词条；目标是前 5,000 词做到高质量。
- **形容词的扎利兹尼亚克字母描述短尾**，不能拿它定长尾重音；长尾除 -о́й 型外一律词干重音。
- **形容词软硬看拼写**（-ий 前是否软辅音），不看索引类型：хоро́ший／ру́сский 是硬变化。
- 名词的性是固有的，形容词的性是一致关系——与 OpenCorpora 比对时名词必须去掉性标签。
- pymorphy3 只是开发期工具，产品里不含分析器，只含展开好的词形表。
- 前端查询逻辑（`dictionary.ts`）是 `search.py` 的镜像，两边分级规则必须一致。
- Service Worker 用**缓存优先**：词包对同一次构建是不可变的，等网络回来才出结果比没有 app 更糟。
- 词包体积有测试守着（< 2500 字节/词条），涨上去先查是不是注释写太满。
- **crosscheck 只能校验拼写，校验不了重音**——OpenCorpora 完全没有重音数据。
  重音类标错时，只有在它改变了拼写的情况下才会暴露（знакомиться 的命令式就是这么发现的）。
  所以重音仍然要靠人核对，不能因为 crosscheck 100% 就以为重音都对。
- **语法性 ≠ 变格型**：мужчи́на／па́па 是阳性但按阴性 -а 变格，见 `declension_gender()`。
- 反身动词的做法是**先按去掉 -ся 的词干变位，再把后缀加回去**；
  元音后加 -сь、辅音和 ь 后加 -ся。单音节词干加后缀后要补标重音（нравь → нра́вься）。
- 名词变格型 6（-я／-ье）与 7（-ия／-ие）只差一处：该用 -е 的地方 7 型用 -и
  （в исто́рии、о мне́нии，但 об иде́е、о здоро́вье）。标错索引只会在这一格暴露。
- `number_only` 会限制生成的数，单数词不再产出复数词形。
- 重读的词尾 е 写作 ё（смеёшься、днём）；不重读时保持 е（чита́ешь）。
- 逃逸元音在 л 之后脱落时留下 ь：па́лец → па́льца（其他位置不留，оте́ц → отца́）。
- **封闭集合要整组收**（星期、月份、带前缀运动动词），缺一个用户看不出来，
  测试里有专门的完整性检查。
- 复习算法：SM-2 变体 + 学习步骤。**遗忘不清零间隔只减半**——重学比冷启动快，
  清零等于惩罚用户来复习。
- 生词本存 localStorage，没有服务器和账号，**这是用户进度的唯一副本**：
  所有写入都要兜底，数据损坏要退化成空生词本而不是崩掉整个 app。
- 词书是按词条 `lv` 标签生成的**视图**，不是另一份清单，避免与词库脱节。

## 领域要点（改数据前先读）

- **重音**：`U+0301` 紧跟重读元音。单音节不标；含 ё 不标；`lemma` 不带重音、`stress` 带。
  前置词可以吸走后词重音（`взять за́ руку`），这是合法的无重音情形。
- **ё/е**：显示保留 ё，检索折成 е（实际文本里 ё 常写成 е）。
- **体（вид）** 是词条的一级结构，不是附注。体对必须双向互指。
- **动物性影响第四格**：anim 复数第四格 = 第二格，inan = 第一格。
- **完成体没有现在时**（只有将来时）；未完成体没有简单将来时。测试已守住这两条。
- **运动动词** uni/multi 必须配对互指（идти↔ходить、ехать↔ездить）。
- 语法标签集与 **OpenCorpora 兼容**，便于形态引擎直接消费。

## 工作约定

- 每个 Milestone 开始前先列实现计划要点，确认后写代码；完成后停下等验收。
- 领域规则有歧义时不要自行拍板，停下来问。
- 与用户沟通用中文，代码注释用英文。
- 词库里的教学注释（`common_errors` / `notes`）用中文写，面向中国学生。
- 拿不准的范式索引和重音，标进 `verify` 字段，不要猜了就写死。

### 批量撰写标准

- 语法字段（`pos` / `gender` / `animacy` / `aspect` / `transitivity` / `zaliznyak`）必填。
- `common_errors` **只在真有坑的词上写**。最初 55 条样例是刻意写满的难样本，
  批量生产照那个密度写会把内容淹掉。
- 每个义项至少一个例句；例句尽量短，降低重音出错概率。
- 词表里没有的词也可以写，但优先补 `coverage --missing` 列出的缺口。
- YAML 陷阱：`en: yes` / `en: no` 会被解析成布尔值，必须加引号（已有测试守住）。

## 常用命令

```bash
cd ruassist
pip install -e ".[dev]"
python -m ruassist.validate data/lexicon   # 校验词库，列出待核对项
python -m ruassist.coverage                # 全部词表覆盖率（默认扫 data/wordlists/）
python -m ruassist.crosscheck              # 生成词形 vs OpenCorpora
python -m ruassist.cli стали --table       # 查词（接受任意词形／拉丁转写）
python -m ruassist.build                   # 编译离线词包（JSON + SQLite）
python -m pytest                           # 全部测试

cd frontend && npm install
npm run dev                                # 开发服务器
npm run build                              # 产出 dist/，纯静态、可离线
npm test                                   # vitest（复习算法、查询、题型）
```

## 关键文件

- `docs/SCHEMA.md` — 词条 schema 定稿 + 形态引擎接口约定（改数据前必读）
- `src/ruassist/schema.py` — schema 的可执行定义，与文档不一致时以代码为准
- `src/ruassist/stress.py` — 重音处理，整个项目的地基
- `data/lexicon/*.yaml` — 手写知识库
- `src/ruassist/morphology/` — 形态引擎（zaliznyak 解析 / 名词 / 形容词 / 动词 / engine）
- `src/ruassist/crosscheck.py` — 与 OpenCorpora 比对，`verify` 清单靠它清
- `src/ruassist/index.py` — 词形→词元索引，歧义全量返回
- `src/ruassist/search.py` — 四级匹配（精确／转写／前缀／模糊）
- `src/ruassist/build.py` — 编译离线词包；bundle 的键名是与前端的契约
- `frontend/src/dictionary.ts` — 前端查询，**与 search.py 是同一套分级逻辑，改一边要同步另一边**
- `frontend/src/srs.ts` — 复习调度，纯函数，好测
- `frontend/src/components/Review.tsx` — 三种题型；重音题是俄语特有的，别删
